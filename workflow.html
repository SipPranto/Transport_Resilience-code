Workflow & Architecture

From raw layers to a single resilience score

Road geometry is overlaid on the flood raster to get an average flood depth per segment. Each segment is classified Operational / Partial / Closed. The surviving network becomes a graph used to test which facilities each ward can still reach. Independently, the travel survey tells us what travellers actually experienced. The three ward-level indices combine into the final TRI.

2 Pipeline

The 10-step run_pipeline() sequence

A single function call executes the entire historical TRI pipeline — dummy data generation through TRI and visualization — with no manual intervention, proving the process is reproducible end to end.

Generate synthetic input data

Creates the 9-ward boundary, road network, flood-depth raster, essential facilities and household travel survey used for this proof of concept.

out: boundary.shp, roads.shp, flood_depth.tif, facilities.shp, travel_survey.csv

Road–Flood Overlay

Zonal statistics compute the average flood inundation depth under each road segment.

in: roads.shp, flood_depth.tifout: road_overlay.shp (+avg_flood)

Road Status Classification

Each segment is labelled by depth threshold: Operational < 0.20 m, Partial 0.20–0.50 m, Closed > 0.50 m.

in: road_overlay.shpout: road_status.shp (+status)

Infrastructure Functionality (IF)

Roads are split by ward boundary; each segment's length is weighted by its status (Operational = 1.0, Partial = 0.5, Closed = 0.0) and summed. IF = effective length ÷ total length × 100.

in: road_status.shp, boundary.shpout: if.csv

Build the surviving road graph

An undirected, length-weighted graph is built from all non-Closed road segments — this is the network people can actually use after the flood.

in: road_status.shpout: in-memory NetworkX graph

Accessibility Index (AI)

For every ward, test whether a path exists from the ward centroid to each essential facility on the surviving graph. AI = reachable facilities ÷ total facilities × 100.

in: road_status.shp, facilities.shp, boundary.shpout: accessibility.csv

Travel Behaviour

Per-trip indicators are derived from the raw survey: delay (after − before travel time), whether the mode changed, whether the trip completed, whether the route changed.

in: travel_survey.csvout: behaviour.csv

Behavioural Adaptation (BA)

Trip-level behaviour is aggregated per ward into three 0–1 sub-scores — completion, delay, and stability — then averaged: BA = (completion_score + delay_score + stability_score) / 3.

in: behaviour.csvout: ba.csv

Master Dataset & TRI

IF, AI and BA are merged on ward_id (BA rescaled ×100 to match IF/AI), then combined: TRI = (IF + AI + BA) / 3, rounded to 2 decimals.

in: if.csv, accessibility.csv, ba.csvout: master_resilience.csv, tri.csv

Visualize & validate

Every vector, raster and CSV product is rendered as a PNG map or chart; a combined contact-sheet overview and a printed end-of-run summary close out the pipeline.

out: output/maps/*.png, printed ward ranking
3 Formulas

Exact calculations used

Road status thresholds

depth < 0.20 m → Operational
0.20 ≤ depth ≤ 0.50 m → Partial
depth > 0.50 m → Closed

Infrastructure Functionality

weights = {Operational:1.0, Partial:0.5, Closed:0.0}
IF = Σ(segment_length × weight) / Σ(segment_length) × 100

Accessibility Index

Graph built from non-Closed roads only.
AI = reachable_facilities / total_facilities × 100 per ward, via shortest-path existence from the ward centroid.

Behavioural Adaptation

completion_score = pct_completed / 100
delay_score = 1 − (avg_delay / max_delay)
stability_score = 1 − (pct_mode_changed + pct_route_changed) / 200
BA = mean(completion, delay, stability), rescaled ×100

Composite Transport Resilience Index

TRI = ( IF + AI + BA ) / 3

4 Reproducibility

Why this pipeline is auditable

Every step writes to disk

Shapefile, GeoTIFF or CSV at each stage — nothing lives only in memory.

Every function is independent

Any stage can be re-run on its own by reading the file the previous stage produced.

One call runs it all

run_pipeline(base_dir) executes every stage from a fresh directory and prints the final ward ranking.
